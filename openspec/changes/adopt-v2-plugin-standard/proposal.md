# Proposal

## Why

Пакет `ocm991` опубликован в npm, но подключение плагина документировано через легаси-ключ `"plugin"` конфига opencode, а метаданные пакета не приведены к текущему стандарту плагинов opencode v2. Из-за этого установка идёт мимо штатного механизма хоста: пользователь правит конфиг вручную; установленный пакет при этом виден в `opencode plugin list`, но не отслеживается и не обновляется штатно — цели `plugin check` / `plugin update` матчатся дословно против литерала `"plugins"` и подключение через легаси-ключ не покрывают. Пакет нужно привести к стандарту v2, чтобы установка и обновление работали штатными командами `opencode plugin add ocm991` и `opencode plugin update ocm991`, как у эталонных server-only плагинов.

## What Changes

- Метаданные npm-пакета приводятся к стандарту плагинов v2: добавляется keyword `opencode-plugin`; server-entrypoint `exports["./server"] → src/plugin.ts` (default-экспорт `{ id, setup }`) подтверждается проверкой и фиксируется в спеке; версия поднимается по semver в зависимости от сути правок (ориентир — patch/minor).
- README переписывается: установка — `opencode plugin add ocm991` как основной путь (ручная форма — массив `"plugins": ["ocm991"]`), обновление — `opencode plugin update ocm991`; легаси-ключ `"plugin"` перестаёт рекомендоваться.
- Типы поверхности Promise-плагина мигрируют на официальный SDK `@opencode/plugin` — SDK как devDependency, импорт только через `import type` (решение согласовано при планировании, design.md Decision 5); SDK не types-only (dependencies включают effect и @opencode-семью), но его runtime-код у потребителя не появляется.
- Подключение на хосте пользователя переводится с легаси-ключа `"plugin"` на канонический `"plugins"` (хост v2.2.5 читает оба ключа, но цели `update`/`check` матчатся дословно против литерала `"plugins"`; одновременное держание пакета под обоими ключами запрещено хостом — дубликат).
- Проверяется полная цепочка на реальном хосте: `opencode plugin add` → `plugin list` → `plugin check` → `plugin update`; публикация новой версии в npm выполняется только по явному подтверждению пользователя.
- Поведение плагина не меняется: форматы хранения, схема памяти, инструменты `memory_save`/`memory_list`, fail-open, кросс-процессные локи и редактирование секретов остаются как есть, все существующие спеки остаются в силе.

## Capabilities

### New Capabilities

- `plugin-packaging`: npm-упаковка плагина как дистрибутива — метаданные пакета, по которым хост распознаёт и подключает плагин; устанавливаемость и обновляемость штатными командами хоста; отсутствие runtime-зависимостей и сборки; соответствие пользовательской документации штатному механизму установки/обновления; неизменность поведения памяти при смене упаковки.

### Modified Capabilities

_(нет: requirements спек memory-context, memory-storage, memory-tools не меняются — изменение касается упаковки и документации, не поведения памяти)_

## Impact

- `package.json` — keywords, version; SDK `@opencode/plugin` добавляется строго в devDependencies (решение по типам — design.md, Decision 5), dependencies не расширяются.
- `README.md` — раздел «Установка» и новый раздел «Обновление».
- `src/plugin.ts` — только типизация поверхности API (`import type` из `@opencode/plugin`, Decision 5); тело плагина и тесты не меняются.
- `AGENTS.md` — включить `@opencode/plugin` в перечень разрешённых devDeps (перечень исчерпывающий; без правки разойдётся с package.json после задачи 3.3).
- Конфиг opencode пользователя (`~/.config/opencode/opencode.json`) — удаление легаси-ключа `"plugin"`, пакет в `"plugins"` (с бэкапом); custom-configs уже на `"plugins"` и не затрагиваются.
- npm-реестр — публикация новой версии `ocm991` только после явного подтверждения пользователя.
