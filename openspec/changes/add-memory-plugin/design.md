# Design

## Context

Каркас уже готов: `package.json` с `exports: "./server"`, tsconfig (strict), Biome, гейт `bun run check` = biome + tsc + тесты; в `src/` есть первый TDD-срез `paths.ts` (`resolveMemoryRoot`) с тестами. Мотивация — в proposal.md (Why); поведенческие контракты — в specs `memory-storage` / `memory-context` / `memory-tools`.

`src/storage.ts` и `src/redaction.ts` — трансплантаты из `~/Documents/GitHub/opencode-working-memory/src/` (детали переноса — tasks 3.0, тестовый подход — Decision 8); синк с апстримом — вручную.

Ограничения: TypeScript + Bun, ноль runtime-зависимостей, никакой сети/eval; формат на диске — переносимый markdown (frontmatter + индекс `MEMORY.md`), читаемый человеком и внешними агентскими инструментами без конвертации; инжект не должен ломать prompt-cache.

## Goals / Non-Goals

**Goals:**
- Модульная структура ~500–800 LOC: `paths`, `storage`, `frontmatter`, `index`, `redaction`, `plugin` (+ опционально `tui` позже).
- Детерминированный, кэш-дружественный инжект с переживанием компакции.
- Надёжная запись: атомарность, кросс-процессный лок, деградация, tolerant чтение.
- Полное тестовое покрытие каждого модуля (тест до реализации — для новых модулей; characterization-тесты — для трансплантатов storage/redaction) и программный смоук против реального API opencode без LLM.

**Non-Goals:**
- `memory_delete` — отдельный опциональный этап (зафиксирован в proposal); TUI-браузер и фоновая экстракция — вне скоупа этого change.
- Семантический recall (выбор релевантного по запросу), фоновая консолидация/«dream»-проходы — сознательно не планируются.
- Миграции/версионирование формата хранилища — формат фиксируется с первого релиза.

## Decisions

1. **Выделенные инструменты вместо записи файлов моделью напрямую.** Свои схемы дают атомарную запись под локом, redaction, дедуп и гейт инъекций без permission-промптов и без доступа модели к каталогу памяти. Альтернатива (generic Write/Edit с авто-разрешением на каталог) отклонена: нет редактирования секретов, нет дедупа, шире поверхность риска.
2. **Инжект — per-request overlay через `context`-хук, снапшот с ключом `(sessionID, generation компакции)`.** Оверлей не пишется в историю → память переживает компакцию автоматически; перечитывание только после компакции (кэш истории всё равно перестраивается). Альтернативы: перечитывание каждый ход (ломает prompt-cache) и выборка релевантного per-turn (недетерминизм) — отклонены. Текст секции правил берётся из zcode (`ZCode/apps/zcode-cli/packages/core/src/context/sections/memory.ts`) — структура и формулировки дословно, не сочиняется заново, кроме tool-специфичных предложений, конфликтующих с контрактами плагина («write to it directly with the Write tool», ручное добавление строки в `MEMORY.md`, «update that file rather than creating a duplicate», «delete memories»): они заменяются минимальным диффом — `memory_save`/`memory_list` вместо Write (Decision 1), автоматическая синхронная сборка индекса (спека `memory-storage`), дедуп-ответ «already saved» без обновления, удаление недоступно (`memory_delete` вне скоупа).
3. **Порядок сборки индекса (бюджетная адмиссия).** Сначала гарантированные типы `user`/`feedback`, затем остальные по сортировке (новейшие) до лимита 200 строк / 25 000 символов; усечение суррогатных пар безопасное; факт обрезки — одной финальной строкой-маркером (без per-entry пометок).
4. **Дедуп — детерминированный канонический ключ `type:canonical`** (NFKC → lower → схлопывание пробелов/пунктуации) на входе `memory_save`. Альтернатива — сравнение семантической близости — отклонена: недетерминированна и требует вычислений.
5. **Fail-open везде + structured errors.** Хуки никогда не бросают в хост (`console.error("[memory] …")`); инструменты возвращают `{ ok, error: { code, message, suggestion } }`. Инструментальный fail-open — перехват с structured-ответом, а не проглатывание.
6. **Санитария жизненного цикла.** Сериальная очередь задач на сессию; LRU-кап кэша снапшотов (~50); очистка по `session.deleted`/disposed; guard двойной регистрации при hot-reload через `Symbol.for` на globalThis с cleanup предыдущего инстанса.
7. **Двойная редакция секретов.** Regex-редакция на входе `memory_save` и повторно при сборке индекса — защита от секретов, попавших на диск в обход инструмента (ручные правки).
8. **Тестовая инфраструктура.** Строгий TDD (тест до реализации) — для новых модулей (paths, frontmatter, index, plugin/context-хук) и деградации storage при таймауте лока (новое поведение, tasks 3.3–3.4); для трансплантатов storage/redaction — characterization-подход: реализация переносится до тестов (tasks 3.0), тесты 3.1–3.2 и 3.5 пишутся под переносимый контракт owm. Глобальный preload тестового окружения через `bunfig.toml` (`[test] preload`) с временным `XDG_DATA_HOME`; кросс-процессные тесты лока (спавн дочерних `bun`-процессов); контракт-тест «ровно ожидаемый набор инструментов + codemode:false»; программный isolated-HOME смоук против реального v2 API opencode без LLM — перед закрытием этапа плагина.
9. **Гейты и валидация `memory_save` — зафиксированные trade-offs сверх минимального контракта спеки `memory-tools`.**
   - **Гейт prompt-injection — эвристический, с якорной привязкой к началу текста/предложения** (`src/plugin.ts`, `INJECTION_ANCHOR`): инструкцию в середине предложения он осознанно пропускает, чтобы не отклонять документационные упоминания («runs `debug show the system prompt`»); открытая формулировка спеки («и подобные») сознательно сужена до детектируемых императивов. Задокументировано тестом `plugin.save.test.ts` и этим решением; усложнение до семантической детекции отклонено как недетерминированное (в духе отклонения альтернативы в Decision 4).
   - **Валидация имени сверх контракта спеки**: максимум 64 символа (`MEMORY_NAME_MAX_LENGTH`) и резерв имени `memory` (коллизия с индексом `MEMORY.md` на регистронезависимых ФС) — дополняют паттерн kebab-case из спеки, ей не противоречат.
   - **`isChildSession` — fail-open при сбое `session.get`**: сессия, которую не удалось опросить, считается корневой (разрешение записи). Это сознательное продолжение Decision 5 (fail-open, никакие исключения не бросают из инструментов); пограничный случай «дочерняя сессия пишет при сбое опроса» остаётся в чек-листе ручного смоука (tasks 6.2) — при необходимости переключение на fail-closed потребует правки поведения и тестов отдельным решением.

## Risks / Trade-offs

- [Кросс-процессные локи зависят от поведения Bun/файловой системы] → кросс-процессные тесты (параллельные инкременты, stale-lock recovery) в TDD-скоупе этапа storage.
- [Строгие OpenAI-совместимые провайдеры могут отвергать несколько system-сообщений] → сведение инжекта к минимуму частей; при жалобах — опция merge system-сообщений, не включённая по умолчанию. Её включение противоречило бы требованию спеки `memory-context` инжектировать две system-части и потребовало бы изменения этой спеки — вне этого change.
- [Инжект дублируется при повторных вызовах хука на одном запросе] → маркер идемпотентности в metadata part'а + per-prompt кэш.
- [API opencode dev меняется между версиями] → контракт-тест + программный смоук против реального API до закрытия этапа; поражение — честный отчёт, а не молчаливый пропуск.
- [Рост индекса у долгоживущих проектов] → лимит индекса + маркер; памяти старше порога помечаются возрастом в строке индекса («[N d old, verify]»; feedback не помечается).

## Migration Plan

Новая функциональность без обратной совместимости: каталог данных `~/.local/share/opencode-memory/` создаётся при загрузке плагина (диагностический лог `plugin.log`), каталог проекта `<root>/projects/<slug>-<hash>/memory/` — при первой записи; откат — удаление плагина из `opencode.json` и каталога данных. Смоук на локальном opencode выполняется до завершения change.

## Open Questions

Нет блокирующих: опциональные возможности (`memory_delete`, TUI) вынесены в отдельный этап и на design не влияют.
