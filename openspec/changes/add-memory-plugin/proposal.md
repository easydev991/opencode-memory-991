# Proposal

## Why

Сессии opencode стартуют без знания о предыдущей работе над проектом: контекст между сессиями теряется, модель заново выясняет правила и решения, уже принятые пользователем. Нужна персистентная память, которую модель пишет и читает нативными инструментами, приватная per-user и отдельная для каждого проекта.

## What Changes

- Новый плагин opencode v2: default-экспорт `{ id, setup }` на пути `./server`, подключение через глобальный `~/.config/opencode/opencode.json` (hot-reload).
- Инструменты модели `memory_save` и `memory_list` (каждый с `options: { codemode: false }`, structured-ответы, без permission-промптов); `memory_delete` — опционально, отдельным этапом.
- Инжект памяти в контекст через `ctx.session.hook("context")`: секция правил + снапшот индекса `MEMORY.md`, детерминированный на сессию.
- Хранилище на диске: `~/.local/share/opencode-memory/projects/<slug>-<hash16>/memory/` — плоские markdown-файлы с frontmatter + индекс `MEMORY.md`; атомарная запись под кросс-процессным локом; редактирование кредов на входе записи.
- Тесты: `bun test` по TDD; гейт `bun run check` (Biome + tsc + тесты) обязателен перед коммитом.

## Capabilities

### New Capabilities

- `memory-storage`: хранилище на диске — расположение и ключ проекта, формат файлов и индекса, атомарная запись под локом, деградация при таймауте лока, tolerant чтение повреждённых файлов, редактирование кредов, дедупликация содержимого, лимит размера индекса, stale-пометка возраста в индексе, синхронное обновление индекса после записи.
- `memory-context`: инжект памяти в контекст сессии — снапшот раз на сессию и его перечитывание после компакции, идемпотентность, отказоустойчивость хуков, санитария per-session состояния, поведение для дочерних сессий.
- `memory-tools`: инструменты модели — нативная регистрация в тул-листе (`codemode: false`), контракты `memory_save`/`memory_list`, structured errors, гейт prompt-injection, тег `<private>`, soft-лимит размера, валидация имени файла (path traversal).

## Impact

- Код: новый `src/` (`paths.ts`, `storage.ts`, `redaction.ts`, `frontmatter.ts`, `index.ts`, `plugin.ts`); `src/paths.ts` уже существует с первым тестом. TUI — вне этого change (опционально позже, отдельный этап — см. design Non-Goals).
- Контракты: `exports: "./server"` в `package.json`; инструменты появляются в нативном тул-листе модели.
- Данные: новый каталог `~/.local/share/opencode-memory/` (пользовательские данные; `XDG_DATA_HOME` перенаправляет корень).
- Конфигурация: ручное подключение плагина в глобальном `opencode.json` (смоук-этап).
- Breaking changes: нет.
