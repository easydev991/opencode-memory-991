# memory-context Specification

## Purpose

Инжект памяти в контекст сессии opencode: что и когда видит модель, как инжект переживает компакцию и остаётся совместимым с prompt-cache, как ведёт себя плагин при сбоях и при записи из дочерних сессий.

## Requirements

### Requirement: Снапшот контекста раз на сессию

В каждую сессию система SHALL инжектировать две system-части: секцию правил работы с памятью и снапшот индекса `MEMORY.md`. Инжект выполняется и в дочерние (субагентские) сессии: снапшот строится по идентификатору сессии независимо от наличия родителя; единственный особый случай для дочерних сессий — запрет записи (см. «Дочерние сессии не пишут память»). Текст инжекта MUST быть детерминированным на сессию: снимается один раз и не перечитывается между запросами той же сессии.

#### Scenario: Стабильный инжект между запросами

- **WHEN** в одной сессии выполнено несколько запросов подряд без записей в память
- **THEN** инжектированный текст идентичен во всех запросах (prompt-cache не ломается)

#### Scenario: Память переживает компакцию

- **WHEN** в сессии прошла компакция истории
- **THEN** модель по-прежнему видит памяти в контексте после компакции

### Requirement: Перечитывание снапшота после компакции

После завершённой компакции система MUST перечитать снапшот из хранилища (ключ кэша: идентификатор сессии + generation последней завершённой компакции); между запросами до компакции перечитывания MUST не происходить.

#### Scenario: Новая память видна после компакции

- **WHEN** память сохранена, затем сессия прошла компакцию
- **THEN** следующий запрос содержит обновлённый индекс памяти

### Requirement: Идемпотентность инжекта

Повторное применение инжекта к одному и тому же запросу MUST не дублировать секции памяти в промпте.

#### Scenario: Повторный проход хука не дублирует

- **WHEN** хук контекста вызывается второй раз для уже обработанного запроса
- **THEN** секция памяти присутствует в промпте ровно один раз

### Requirement: Отказоустойчивость хуков

Любая ошибка при сборке инжекта (отсутствующий каталог, нечитаемый файл, сбой файловой системы) MUST не приводить к исключению в хост-процесс: ошибка логируется, сессия продолжается, инжект возвращается в деградировавшем или пустом виде.

#### Scenario: Хранилище недоступно — сессия работает

- **WHEN** каталог памяти не существует или нечитаем
- **THEN** сессия продолжается без инжекта памяти, ошибка зафиксирована в логе

### Requirement: Санитария per-session состояния

Плагин SHALL ограничивать кэш снапшотов по сессиям (LRU, ~50 сессий) и MUST освобождать состояние сессии при её удалении или диспозе плагина.

#### Scenario: Кэш не растёт неограниченно

- **WHEN** за время жизни процесса плагина обслужено больше сессий, чем лимит кэша
- **THEN** размер кэша не превышает лимит, состояние вытесненных сессий освобождено

#### Scenario: Очистка при удалении сессии

- **WHEN** сессия удалена (событие удаления сессии) или плагин диспоузится
- **THEN** связанное с сессией состояние удалено из кэша

### Requirement: Дочерние сессии не пишут память

Дочерняя сессия (имеющая родительскую) MUST не сохранять памяти: записи из субагентов не попадают в хранилище.

#### Scenario: Запись из субагента отклоняется

- **WHEN** инструмент сохранения вызывается из дочерней сессии
- **THEN** память не записана, инструмент возвращает structured-ответ с объяснением
